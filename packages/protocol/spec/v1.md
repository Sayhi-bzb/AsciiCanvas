# CharDesk Text Protocol v1

This specification defines how plain Unicode text and ANSI-styled text map to a deterministic two-dimensional cell surface. It does not define an editor document, scene graph, animation, font, or rendering technology.

## Input

The input is one Unicode string. A consumer selects one syntax mode:

- `auto` recognizes standard ANSI controls and recognizes ESC-less controls only when they contain a supported operation. This is the default.
- `plain` recognizes no ANSI controls.
- `ansi` recognizes standard and ESC-less controls, including unknown numeric SGR codes.

Standard SGR uses `ESC[...m`. ESC-less SGR omits the U+001B prefix and uses `[...]m`, for example `[38;2;255;0;0mred[0m`.

## Text layout

- CRLF, CR, and LF each produce one line break and normalize to LF in plain output.
- Tab advances to the next tab stop. The default tab size is four cells.
- Leading spaces, trailing spaces, empty lines, and a final empty line are preserved.
- Input is segmented into Unicode extended grapheme clusters by a conforming `Intl.Segmenter`. Protocol v1 pins its East Asian Width data to Unicode 17.0; implementations must pass the normative fixtures.
- East Asian Width `W` and `F` graphemes occupy two cells. Emoji presentation, emoji modifier, keycap, regional-indicator-pair, and extended-pictographic ZWJ graphemes occupy two cells. Other graphemes, including East Asian Width `A`, occupy one cell.
- Coordinates start at `x = 0`, `y = 0`. Each grapheme advances `x` by its cell width. A line break resets `x` and increments `y`.
- Document width is the largest completed line width. Document height includes preserved empty lines. Empty or control-only input is `0 × 0`.

## SGR styles

Styles remain active until changed or reset. The caller supplies the inherited default style; absent default colors remain inherited rather than becoming hard-coded black or white.

| Codes | Meaning |
| --- | --- |
| `0` or empty | Reset to the caller default style |
| `1` / `22` | Enable / disable bold |
| `3` / `23` | Enable / disable italic |
| `4` / `24` | Enable / disable underline |
| `7` / `27` | Enable / disable inverse |
| `9` / `29` | Enable / disable strike |
| `30–37`, `90–97`, `39` | ANSI foreground / bright foreground / default foreground |
| `40–47`, `100–107`, `49` | ANSI background / bright background / default background |
| `38;5;N`, `48;5;N` | xterm 256-color foreground / background |
| `38;2;R;G;B`, `48;2;R;G;B` | RGB foreground / background |

Color components and palette indexes are clamped to `0–255`. Inverse remains an attribute in parsed data; a renderer resolves it by swapping effective foreground and background. If one side is inherited, the renderer uses its own inherited default for that side.

An unknown numeric SGR code is ignored and reported when its sequence is consumed. An incomplete extended-color group is malformed. In `auto`, an unknown-only or malformed ESC-less sequence remains visible text. A malformed standard escape drops the U+001B control, preserves subsequent visible characters, and reports a diagnostic. Other unsupported C0 controls are ignored and reported.

## Hyperlinks

Protocol v1 recognizes OSC 8 links in both forms:

- Standard: `ESC]8;;URI ST label ESC]8;; ST`, where ST is `ESC\` or BEL.
- ESC-less: `]8;;URI\label]8;;\`.

CharDesk output using this protocol may place an SGR sequence immediately after an ESC-less URI and may close the link immediately before an SGR reset; both boundaries are valid. Parsed `href` values are untrusted strings. A renderer must apply its own URL-scheme allowlist before creating a navigable link.

Markdown links are not part of the protocol.

## Parsed model

A conforming parser returns:

- protocol version, original source, normalized plain text, cell width and height;
- whether any ANSI or OSC control was consumed;
- diagnostics with source offsets;
- one record per visible grapheme containing `x`, `y`, `width`, `text`, active style, and optional `href`.

The model is rendering-neutral. Consumers may render it with HTML, SVG, Canvas, a terminal, or another surface.

## Compatibility

The fixtures in [`../fixtures/v1.json`](../fixtures/v1.json) are normative examples. A change that alters their cell coordinates, widths, styles, plain text, or control interpretation requires a new protocol version. npm package versions follow SemVer independently.
