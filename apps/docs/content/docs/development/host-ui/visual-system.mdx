The visual ownership path has one direction:

`CSS semantic token -> shared rx recipe -> shared UI primitive -> widget composition`

- [`src/app/index.css`](https://github.com/Sayhi-bzb/CharDesk/blob/main/src/app/index.css)
  owns semantic color, surface, elevation, and viewport-layer tokens.
- [`src/shared/styles/recipes.ts`](https://github.com/Sayhi-bzb/CharDesk/blob/main/src/shared/styles/recipes.ts)
  owns reusable visual and interaction recipes.
- [`src/shared/ui`](https://github.com/Sayhi-bzb/CharDesk/tree/main/src/shared/ui)
  owns domain-neutral structure and accessibility; `src/widgets` composes it.

`shadow-host`, `shadow-overlay`, and `shadow-dialog` are the elevation ladder.
Viewport surfaces use semantic layer tokens; product instances do not assign raw
overlay tiers or recreate shared surfaces.

Persistent Canvas chrome uses the `floatingHost` recipe. Toolbars, Inspector,
Minimap, and the desktop Sidebar therefore share one borderless host surface,
radius, and light elevation. Transient portal content continues to use the
stronger overlay surface.
