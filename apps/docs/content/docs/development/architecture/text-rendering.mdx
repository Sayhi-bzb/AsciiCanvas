---
title: External Text Rendering
description: Plugin boundary for converting pasted source text into editable Canvas cells.
---

External plain text crosses one runtime before paste:

`clipboard source -> document text-rendering runtime -> plain text or styled protocol cells -> Canvas command`

[`document/public.ts`](https://github.com/Sayhi-bzb/CharDesk/blob/main/src/domains/document/public.ts)
owns the plugin registry, active profile, persistence, and conversion result. `actions`
only snapshots clipboard data and passes the result to Canvas. GridMap remains the only
editable content store; renderer settings affect future paste and never reinterpret existing
cells.

Rendering has four stages: syntax decode, structural transform, style composition, and cell
layout. ANSI is a decoder backed by `@chardesk/protocol`; Markdown is a structural transformer
backed by `remark` and `remark-gfm`; the compositor projects ANSI spans through Markdown source
ranges; the protocol layout is the only stage that owns grapheme segmentation, CJK width, tabs,
and coordinates. Shiki code tokens join the same fragment stream and are never serialized
through ANSI.

Auto composes explicit ANSI and Markdown instead of selecting one renderer for the whole source.
An ESC-less empty reset (`[m`) is ambiguous evidence and cannot activate ANSI by itself, preventing
Markdown links beginning with `[m` from losing characters. Standard escapes, OSC 8, and non-empty
supported SGR are explicit. Forced ANSI still accepts `[m`. When both syntaxes style one range,
ANSI foreground, background, and OSC 8 href win; text attributes merge; Markdown controls visible
structure. `TextRenderResult.pipeline` records the applied stages.

Markdown renders Codex-style headings, inline code, links, blockquotes, lists, thematic
breaks, fenced code, and GFM tables at natural content width. Layout never depends on the
viewport, zoom, or paste position. Disabled inline rules consume delimiters without styling;
disabled block rules preserve their source slice. Raw mode preserves all delimiters. Renderer
results may be asynchronous, and clipboard commands await them before mutating Canvas.

The independent Mermaid rule converts `mermaid` fenced blocks through the private
`@chardesk/chargraph/mermaid` plugin into plain Unicode before protocol layout. CharGraph owns
the pluggable source-to-Unicode contract; the Mermaid plugin owns its vendored text renderers and adapts graphemes to `@chardesk/protocol` cell
widths; it excludes the upstream SVG, ELK, ANSI, and theme pipelines. It is loaded on demand
and falls back to the complete fenced source with a diagnostic for unsupported, invalid, or
oversized input. Disabling Mermaid keeps the inner source as an ordinary code block.

`TextRenderProfile.renderTheme` stores optional semantic token overrides; the resolved Renderer
Theme is independent from the host UI theme. `markdownColors` stores optional rule-slot overrides.
Style precedence is explicit ANSI, rule-slot override, Renderer Theme token, then inherited paste
style. The rule behavior map in `rendering/theme.ts` owns each slot's token or inheritance default.
Quote and heading colors belong to their markers; inline code owns foreground and background
slots; table headers own foreground and background slots while separators are independent.
Fenced code remains owned by Shiki token colors, and Mermaid inherits the paste foreground unless
overridden. Persisted legacy rule colors migrate to the corresponding slots. Like every renderer
setting, style changes affect future paste only because Canvas stores materialized cells.

Verification lives in
[`runtime.test.ts`](https://github.com/Sayhi-bzb/CharDesk/blob/main/src/domains/document/rendering/runtime.test.ts)
and the clipboard integration tests.
